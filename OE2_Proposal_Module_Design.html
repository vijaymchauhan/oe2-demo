📋   How the Proposal Module Works — End-to-End Flow
1
✏️
Create Proposal
User opens the Proposal tab and clicks Add. Selects an existing customer or types a prospect name. Fills in job details and adds line items with pricing. Saves as Draft.
2
📤
Send to Customer
User clicks Print or Email on the Edit screen to deliver the proposal. Status is updated to Sent to track that the customer has received it.
3
🔄
Revise if Needed
If the customer requests changes, user clicks New Revision. A copy is created with the next revision number (e.g., 10000.01 → 10000.02). The prior version is kept for history.
4
✅
Customer Approves
Status is updated to Approved. The Convert to Job button becomes available. If declined, status is set to Rejected and no job is created.
5
🔄
Convert to Job
User clicks Convert to Job, enters the Customer Job #, and selects which line items to include. System creates the Job record(s) automatically and links them back to the proposal.
6
📁
Job(s) Created
New Job(s) appear in the Jobs module with all billing details pre-filled from the proposal. The proposal record is marked as converted and shows the linked Job number(s).
📌 Proposal Numbering
  • New proposals are auto-numbered starting at 10000.00
  • Each revision increments the decimal: 10000.01, 10000.02…
  • The base number groups all revisions together in the listing
  • Proposal numbers and Job numbers share the same sequence so no number is ever duplicated
📌 Convert to Job — Job Creation Rules
  • Single item selected → Creates 1 Main Job with that item's amount
  • Multiple items selected → Creates 1 Main Job ($0.00) + 1 Extra Job per item, each with its own amount
  • Customer Job # entered in the modal is saved on every created Job record
  • ALT (Alternate) items are excluded from the printed Subtotal but can still be converted
📌 Status Meanings
  • Draft — Proposal is being prepared, not yet sent
  • Sent — Delivered to customer, awaiting response
  • Approved — Customer accepted; Convert to Job is now available
  • Rejected — Customer declined; proposal is closed, no job created
📌 Existing Customer vs. Prospect
  • Existing Customer — Select from the OE2 customer database using the Lookup button
  • Prospect — Type the customer's name as free text (they are not yet in the system). When they become a customer, the proposal can be linked later
  • All proposals — whether for existing customers or prospects — appear in the same listing
Screen 1 — Proposal Listing Page

What this screen does

This is the main entry point for the Proposal module. It shows all proposals in a searchable, scrollable grid. Users can find any proposal quickly by searching on Proposal #, Customer Name, Customer Job #, Customer PO #, or Project Manager. The Status filter lets users see only Drafts, Sent, Approved, or Rejected proposals at a glance.


How to use it

  • Click the Proposal tab in the main navigation to open this screen.
  • Use the Search Proposals sidebar on the left to filter the list. Enter one or more search fields and click Search. Click Clear to reset all filters.
  • Click any Proposal # link in the grid (shown in dark red) to open that proposal for editing.
  • Click Add (List/Add tab) to create a brand-new proposal.

Grid columns explained

  • Proposal Date — The date the proposal was originally created.
  • Proposal # — Unique number in the format NNNNN.RR where RR is the revision number (00 = original, 01 = first revision, etc.). Click to open and edit.
  • Customer Name — The customer or prospect this proposal was written for.
  • Job Name / Description — The project name and scope summary.
  • Status — Current state of the proposal: Draft Sent Approved Rejected
  • Total ($) — The sum of all line items on the proposal (auto-calculated, not manually entered).

Screen 2 — Create / Add New Proposal

What this screen does

This screen is used to write a new proposal for a customer or a prospective client. The system automatically assigns the next Proposal Number (shown in green, e.g., 10004.00). The user fills in the customer, job location, scope of work, and adds individual line items with pricing. The total is calculated automatically from the items — no manual amount entry needed.


Step-by-step: How to create a proposal

  • Step 1 — Choose Customer Type: Select Existing Customer and use the Lookup button to find them in OE2, or select Prospect (New) and type their name directly — no lookup required for prospects.
  • Step 2 — Fill in Job Details: Enter Job Name, Floor, Address, City, State, Zip, and a Description of the scope of work. These fields will also appear on the printed proposal.
  • Step 3 — Set Status & Tax: Status starts as Draft. Select the correct Tax Code (e.g., NYC – 8.875%). Update Status to Sent after emailing or printing for the customer.
  • Step 4 — Add Line Items: In the Proposal Items section, click + Add New Item for each service being quoted. Enter the Description, Quantity, and Unit Price. The Total is calculated automatically. Use the ALT * checkbox to mark any item as an Alternate (excluded from the main subtotal on the printed proposal).
  • Step 5 — Save: Click Save Proposal to save and return to the listing, or continue editing.

Key field notes

  • Proposal # (auto) — System-generated. Do not edit. Format: NNNNN.00 for new, NNNNN.01+ for revisions.
  • ALT * checkbox on items — Marks a line item as an Alternate. On the printed proposal, ALT items appear separately and the standard subtotal note reads "*Subtotal excludes alternates."
  • Exclusions / Notes — Standard exclusions like "removals, stripping, overtime" that print at the bottom of the proposal.
  • CPC — Customer Project Contact. This is the person the proposal is addressed to ("ATTN:" on the printed proposal).
  • PM/Biller — The estimator's name printed on the proposal as "Estimator."

Screen 3 — Edit Proposal (Action Buttons)

What this screen does

This is the same form as Create Proposal, but it is opened by clicking an existing Proposal # from the listing. In addition to editing all proposal fields, this screen shows an Actions toolbar at the top with four key buttons. These buttons drive the full proposal lifecycle.


Action buttons explained

  • 📄 New Revision — Creates a copy of this proposal with the next revision number (e.g., 10000.01 becomes 10000.02). The current version is preserved as a historical record and becomes read-only. Use this when the customer requests changes to an already-sent proposal.
  • 🔄 Convert to Job — Only available when Status is Approved. Opens the Convert to Job dialog where the user selects which line items to carry over to billing and enters the Customer Job #. The system then creates the Job record(s) automatically. See Screen 4 for full details.
  • 🖨️ Print — Generates the formatted Albert Pearlman proposal document (matching the standard company proposal format). All fields from the proposal are automatically populated. The print layout is shown in Screen 5.
  • ✉️ Email — Sends the proposal as a PDF attachment to the customer's email address on file. The email uses the standard company template. Status should be updated to Sent after emailing.

Screen 4 — Convert Proposal to Job (Modal)

What this screen does

This dialog opens when the user clicks Convert to Job on an Approved proposal. It lets the user choose which line items should be carried over into the Jobs module for billing, and enter the Customer's own job reference number. The system then creates the Job record(s) automatically.


Job creation rules — important

  • If 1 item is selected: The system creates one Main Job with that item's description and amount. The Job number will be the same base number as the proposal (e.g., Proposal 10001.00 → Job 10001).
  • If 2 or more items are selected: The system creates one Main Job with Amount $0.00 (the parent/container job) plus one Extra Job for each selected item — each Extra Job carries its own description and amount. This keeps individual billing lines separate and traceable.

How to use it

  • Step 1 — Enter the Customer Job # (the reference number assigned by the customer). This is saved on all created Job records.
  • Step 2 — Check the items you want to include in billing. Uncheck any items you do not want converted (e.g., items not yet approved by the customer).
  • Step 3 — Review the "Jobs to be Created" summary at the bottom to confirm what will be created.
  • Step 4 — Click Create Jobs. The system creates all Job records and links them back to this proposal. The proposal status does not change — it remains Approved for reference.

Screen 5 — Proposal Print Preview

What this screen does

Clicking Print on the Edit screen opens a formatted, print-ready proposal document. This matches the standard Albert Pearlman proposal format exactly. All fields are automatically populated from the proposal record — the user does not need to re-enter anything. The document can be printed directly or saved as a PDF to email to the customer.


How fields map from OE2 to the printed proposal

  • ATTN — From the CPC (Customer Project Contact) field on the proposal
  • Company — From the Customer Name (or Prospect Name) field
  • Address / City, State, Zip — From the Job Address, City, State, Zip fields
  • Date — From the Proposal Date field
  • WO# / PO# — From the Customer PO / Change Order # field
  • AP# — From the Proposal # (e.g., 10001.00)
  • Estimator — From the PM/Biller field
  • Job Name / Floor / Job Detail — From the corresponding form fields
  • Line items — Each row from Proposal Items appears as a line with its Amount
  • ALT * column — Items with the ALT checkbox checked are flagged with a ✓ in the ALT column and their amount is excluded from the Subtotal
  • Exclusions / Notes — From the Exclusions / Notes text field
  • Subtotal / Tax / Total — Auto-calculated: Subtotal = sum of non-ALT items; Tax = Subtotal × Tax Code rate; Total = Subtotal + Tax
