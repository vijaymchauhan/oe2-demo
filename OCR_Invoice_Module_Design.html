System Overview — Invoice OCR Automation

How the system works

The Invoice OCR Automation module is a background Windows Service that monitors a configured folder on the server. When invoice files (PDF, JPG, PNG) are dropped into that folder, the service automatically picks them up, runs OCR (optical character recognition) to extract invoice data, and places results into a review queue inside OE2. After a user reviews and approves, the invoice data is linked to a Paint Cost job in OE2.

  • No manual upload needed — just drop files in the monitored folder and the system handles the rest.
  • OCR Confidence scoring — each extracted field gets a confidence % (green = high, orange = medium, red = low). Low-confidence fields are highlighted for manual correction.
  • OE2 Integration — approved invoices are directly linked to existing OE2 jobs/paint cost records.

📊 OCR Confidence Rules
  • 85%+ → High (green) — auto-queue
  • 50–84% → Medium (orange) — review flagged
  • Below 50% → Low (red) — manual required
  • Any low field → whole invoice → Manual Review
📁 Folder Movement Rules
  • Success → moved to Completed folder
  • OCR Fail → moved to Failed/Error folder
  • Original filename preserved with timestamp
  • Duplicate filenames get suffix: _001, _002
🔧 Windows Service Rules
  • Runs as a background Windows Service
  • Configurable scan interval (default: 5 min)
  • Auto-restarts on failure
  • Logs all activity to DB + log files
🔗 OE2 Integration Rules
  • Invoice links to OE2 Job via AP Number
  • Total Paint Cost written to Paint Cost module
  • Approved invoices are read-only in OCR module
  • Bulk approval supported (multiple invoices at once)

⚠ Critical OCR Challenge: AP/PO Number
Every vendor labels the PO field differently: "RO No.", "PO:", "PURCHASE ORDER:", "PO Number:", "PO#". Sherwin-Williams embeds it as "AP76228/7 WEST 34TH" — OCR must strip the AP prefix and trailing text. This field requires highest verification priority.
⚠ Critical OCR Challenge: Invoice Total
Sherwin-Williams uses "CHARGE" instead of "Total". Aboff's and Eastern show a "Total" in the page header. Merit uses "Account Charges" as the final payable amount. OCR must map all these to the single Total Paint Cost field.
ℹ Date Extraction
Eastern and Aboff's (both Rundoo POS) embed the date inside "By: Name Date Time" text — e.g., "By: Danielle May 18, 2026 9:05am". OCR must parse the date from this string rather than a labeled field.

Screen 2 — Folder Monitoring Configuration

What this screen does

Administrators configure the folder paths and scanning behavior of the Windows Service here. Changes take effect after clicking Save — the service picks up the new settings without a restart. The Test Connection button verifies all three folder paths are accessible on the network before saving.

  • Input Folder — where users (or a scanner/email system) drop new invoice files
  • Completed Folder — successfully processed invoices are moved here automatically
  • Failed Folder — invoices that could not be OCR-processed are moved here for manual handling
  • Scan Interval — how often the service checks the input folder (minimum: 1 minute)

Screen 3 — Invoice Processing Queue

What this screen shows

All invoice files detected from the monitored folder appear here. Each row shows the file name, when it was detected, its current processing status, OCR confidence score, page count, and available actions. Use the status tabs to quickly filter by what needs attention. The Review Required tab is the most important — those are invoices that need a human to verify the extracted data before they can be approved.

  • Retry — re-runs OCR on a failed invoice (useful after service configuration changes)
  • Preview — opens the Invoice Viewer side-by-side with the extracted data
  • Review — opens the Invoice Detail screen to correct low-confidence fields
  • Confidence shown as color-coded percentage: green=high, orange=medium, red=low

Screen 4 — OE2 Invoice Management

What this screen does

This is the main list of all invoices that have been successfully processed by OCR and are ready to be linked into the OE2 Paint Cost module. From here, users select one or more invoices, review their details, and click Add to Paint Cost to push the data into the appropriate OE2 job. Bulk selection allows approving multiple invoices at once.

  • Add to Paint Cost — links the invoice's Total Paint Cost and AP Number to the matching OE2 job
  • Approve — marks invoice as verified/approved without immediately linking to Paint Cost
  • Edit — opens the Invoice Detail screen to modify extracted fields before approval
  • Invoices remain here until explicitly deleted or archived — you can always reference past invoices

Screen 5 — Invoice Detail / Edit

What this screen does

The detailed view for a single invoice. Each field extracted by OCR is shown alongside its confidence score. Fields with low confidence (below 50%) are highlighted in red — these need manual correction before the invoice can be approved. Fields with medium confidence are shown in orange as a caution. After correcting any fields, click Save & Update then Approve.

  • Confidence badge beside each field — instantly shows which fields need attention
  • Low confidence fields are highlighted with a red border — don't skip these
  • Overall OCR Score at the top shows the average confidence across all fields
  • Save & Update saves without approving (useful to save progress); Approve finalizes the invoice

Screen 6 — Invoice Viewer

What this screen does

A side-by-side view showing the original invoice document (left) next to the OCR-extracted data (right). This allows users to visually compare the actual invoice with what the OCR captured, making it easy to spot and correct errors.   • If OCR failed completely, a manual data entry form appears in the right panel instead

Screen 7 — Manual Invoice Entry

When to use this screen

When the OCR engine completely fails to read an invoice (torn paper scan, handwritten invoice, very low quality image), or when there is no file to upload at all, use this screen to enter the invoice data manually. You can still attach the original file for reference even if OCR cannot process it.

  • Upload Attachment — attach the original invoice file for record-keeping (optional)
  • Save as Draft — saves the entry but keeps it in Draft status for someone else to complete/verify
  • Submit for Approval — marks as ready for manager review and approval

Screen 9 — Error & Audit Logs

What this screen shows

Complete audit trail of everything that happens in the OCR module. Use the tabs to switch between log categories. All logs can be downloaded as a CSV file for external review or archiving. The User Activity tab shows who made manual edits to invoice data and what they changed.

  • OCR Errors — files that failed processing, with the specific error reason
  • Service Logs — Windows Service start/stop, scan cycles, config changes
  • File Logs — every file detected, moved to Completed or Failed folder
  • User Activity — who approved, edited, or deleted invoice records and when

Screen 10 — Notifications & Alerts

What this screen does

Shows all active system alerts and lets administrators configure which events trigger notifications and where they are sent. Alerts appear both in this screen and as a badge on the Notifications sidebar menu item. Critical alerts (service stopped, folder inaccessible) should be configured to send email immediately.

  • Active Alerts — current unresolved issues that need attention (shown at the top)
  • Email Notification Settings — configure who receives alerts and for which event types
  • Notification History — log of all past alerts and when they were resolved
